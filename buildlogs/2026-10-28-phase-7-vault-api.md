# Phase 7: vault API
Date: 2026-10-28

## Why
The server side of the personal vault: encrypted items and folders, sync by
revision, optimistic concurrency, trash, batch import and the purge job.
Implements the Phase 6 contract. Decisions §16.

## What changed
- apps/api/prisma/schema.prisma: `VaultItem`, `Folder`, `VaultState` (revision + tombstone floor), `VaultTombstone`; enums `item_type`, `vault_object_kind`
- apps/api/src/modules/vault/: repository (transaction queries, REPEATABLE READ sync snapshot, cross-user purge/prune), service (CRUD, 409 conflicts, batch import, `purgeExpired`), routes `/vault/*` (body limits, per-user rate limits)
- apps/api/src/jobs/: `vault.purge-trash` daily 04:00 UTC; worker passes the vault module
- apps/api/src/lib/errors.ts: `conflict(message, details?)`
- packages/types/src/vault.ts: `VAULT_RETENTION` (trash 30 d, tombstones 90 d)
- apps/api/test/integration/vault.test.ts (+ harness `PUT`), src/modules/vault/vault.service.test.ts
- apps/api/vitest.config.ts: `fileParallelism: false`

## Notes / gotchas
- Migration `20261029001017_vault`, generated by the user.
- Every write starts with the `vault_state` upsert: that row lock is what
  keeps revisions in commit order. Don't move checks before it.
- Sync returns the whole vault in one response; paging can come later if
  big vaults need it.
- Verified by the user 2026-10-28.
